# NO SUCH PERSON《查无此人》时长与内容扩展方案


> ⚠️ **当前形态声明（2026-11-21 / Build 1.2）**：本文件含早期设计记录，其中「一局 / 15 房房间池 / 门厅 / 每日种子 / 速通榜」等均为**已废弃草案**——相关代码已从 `game.js` 移除，成品只有 **5 关手工战役**（列名/点名/空档/升格/注销），关卡在精不在多，每关有不可替代的存在意义。请以 `README.md` 与 `docs/NO_SUCH_PERSON_五关设计说明.md` 为当前口径；本文以下内容仅作历史设计档案保留。

> 版本 v1.0 ｜ 2026-11-15 ｜ 主理人起草
> 目的：当前 5 关 ≈ 10 分钟，离 Steam 氛围向独立游戏「2 h+」的期望差一个数量级。本文给出几条路、一个推荐、以及分阶段落地计划。

---

## §1 现状与缺口（先算清楚）

| 项 | 现状 |
|---|---|
| 关卡数 | 5（手工，46–60 列 / 关） |
| 单关时长 | 40–70 s |
| 单轮纯通关 | ≈ 4–6 min |
| 含死亡重试（约 ×1.5–2） | ≈ 8–12 min |
| Steam 同类期望（含重玩） | 2–4 h |
| **缺口** | **约 10–20 倍** |

**关键判断**：靠"每关 60 s 的手工关"堆到 2 h，需要 60–90 关，每关都要人工摆光位 / 断崖 / 碎片——这是**每分钟成本最高**的一条路，而且最容易让玩家疲劳。所以不能只加关。

---

## §2 四条路（成本 / 时长 / 重玩性）

| 方案 | 单次时长 | 重玩性 | 内容成本 | 结论 |
|---|---|---|---|---|
| **A 只加手工关** | 每关 +1 min | 低 | 高（人日/分钟最高） | 不推荐单用 |
| **B 房间池 + 程序拼装（结构轻肉鸽）** | 每轮 18–25 min | 高（随机） | 中（做 30–50 块 room piece） | **★推荐** |
| **C 元进度（memory / depth 解锁）** | 每次 +? | 极高 | 低–中 | 与 B 组合 |
| **D 挑战模式（每日种子 / 无痕 / 速通）** | 5–15 min/次 | 极高 | 低（复用 B 的房间） | 锦上添花 |
| **E 多结局** | 3 次通关 | 中 | 低（已完成） | 已有 |

**推荐组合：B + C + D + E。**

---

## §3 推荐结构的数字（怎么真的到 2 h）

- **一轮 run = 3 幕 × 5 房间 = 15 个房间**，约 **18–25 min**（含死亡重试）。
- **房间池 36 块**（12 类 × 3 难度档），按幕抽签，每块 room 预置出入口 + 保底通路（保证有解）。
- **三幕难度**：幕 1 灯少而慢；幕 2 引入激光；幕 3 灯 + 断崖 + 活碎片。
- **元进度**：22 处 memory 位点跨 run 累积，解锁房间变体（"你死过的地方，这次换了个样子"）。
- **重玩钩子**：3 结局 × 集齐 22 memory × 每日种子。

**时长估算**：

| 目标 | 时长 |
|---|---|
| 首次到任一结局 | ≈ 25 min |
| 三年结局全看 | ≈ 75–90 min |
| 集齐 22 记忆 + 打每日 | +45–60 min |
| **合计** | **2–2.5 h**，且随机房间让二周目不重复 |

---

## §4 分阶段落地

**Phase 1（先做，立刻把"单轮"从 5 min 变 20 min）**
把现有 5 张「整关」拆成 ~15 个 **room piece**（每个 14–22 列），加一个 `assembleRun(seed)` 按幕拼装；打完 15 房 = 一轮结束，回标题。

**Phase 2（难度与可复现）**
每个 room 做 3 个难度档（灯数 / 相位 / 断崖）；随机种子可复现；每日种子（日期 → 种子）。

**Phase 3（元进度与发行）**
depth 解锁房间变体；成就（已有数据层）；Steamworks 集成（成就 / 云存档 / 排行榜）。

---

## §5 便宜的先手（不动结构也能加时长）

这几条几乎零成本，做完就能提升"重玩不重复"：

1. **光相位随机化**：同一关每次进入，灯的初始相位/速度轻微随机 → 同关不同体验。
2. **每日种子**：日期决定一套种子，所有人当天同一套布局，社区可晒成绩。
3. **无痕挑战**（已有 `runClean`）：单独模式，全程不被看见通关。
4. **速通榜**：已有 `save.best`，按关/按 run 计时排行。

---

## §6 风险（必须提前想）

| 风险 | 缓解 |
|---|---|
| 程序拼装的房间可能无解/太难 | 每块 room 预置出入口 + 保底通路；上线前跑自动"可解性校验" |
| 随机削弱手工关的情感节奏（memory 演出不知道落在哪关） | 用「固定剧情房 + 随机填充房」混合，演出固定在剧情房 |
| 体量膨胀导致手感稀释 | 每 3–4 个房间引入一个新元素，别一次性堆满 |

---

## §7 结论

把「5 个手工关」升级为「**房间池 + 15 房一轮的结构轻肉鸽**」，配元进度与每日种子——这是把时长从 10 分钟做到 2 小时+、且成本可控的**唯一现实路径**。

**下一步建议**：先做 Phase 1（拆房间 + `assembleRun`）。一周内就能让"单轮时长"从 5 分钟变成 20 分钟，之后所有扩展（难度、元进度、每日）都长在这个骨架上。
