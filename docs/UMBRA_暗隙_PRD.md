### 1.1 一句话定义

**你是一块黑色方块。贴上地图里的黑色砖块、停下来，表情会消失，你成为墙的一部分；一旦移动，眼睛睁开，光就会找到你。**

### 1.2 这是个什么游戏

2D 横版光影潜行平台。玩家扮演一块纯黑立方体，在由**灰色硬砖**与**黑色软砖**构成的极简关卡中前进，收集 3 枚碎片后进入传送门。关卡中分布着持续运动的光源（扫描灯锥、脉冲点光、间歇激光），**光是致命的**——但只在"你是你"的时候致命。

核心创意不在"躲开光"，而在**"变成墙"**：

> 黑砖是同类材质。贴住黑砖并静止 0.08 秒，方块的眼睛闭合、描边消失、颜色与砖块完全一致，与地图融为一体；此时任何光照判定全部跳过。
> 一旦你移动、起跳、或脚下不再是黑砖，眼睛重新睁开——黑暗里唯一发亮的东西就是你的眼睛，它会把光引过来。

于是整个游戏只有一个问题反复被追问：**"我什么时候必须变回自己？"**

### 1.3 与参考产品的定位差异

| 维度 | Sqube Darkness（参考） | UMBRA（本产品） |
|---|---|---|
| 藏身方式 | 在阴影中移动、躲避探照灯与陷阱 | **主动与黑砖伪装**：状态切换而非位置躲避 |
| 玩家的"暴露信号" | 无显式信号，靠位置判断 | **眼睛**：睁开=可被击中，闭合=免疫，视觉即状态 |
| 节奏本质 | 时机跑酷（timing is everything） | 节奏 + 停走决策（何时停下、何时赌一次冲刺） |
| 失败反馈 | 触碰即死，重开 | 0.6 秒"灼烧条"渐进死亡，允许擦边与悔步 |
| 关卡语言 | 陷阱与灯光的堆叠 | 材质语言：硬砖=地形，黑砖=安全岛，光=禁区 |
| 技术栈 | Unity 6 WebGL 构建 | 原生 Canvas 2D + WebAudio，**60 KB，零依赖** |

差异不是"换皮"，而是把参考产品里"阴影"这个模糊概念**收敛成一个可被看见、可被操作的状态机**。

### 2.1 产品目标（可验收）

| 编号 | 目标 | 量化指标 |

| G4 | 手感达到商业可比水平 | 输入到画面反馈 ≤ 1 帧；固定步长 120 Hz 模拟，无穿模 |
| G5 | 极低门槛接入 | 首屏可交互 < 1.5 秒（本地），全量资源 < 100 KB，无外部请求 |
| G6 | 全端可玩 | 桌面 Chrome/Edge/Safari/Firefox 最新两版 + iOS/Android 主流浏览器 |

### 2.2 目标用户

| 分层 | 画像 | 需求 | 占比预估 |
|---|---|---|---|
| 核心用户 | 16–30 岁，常在 CrazyGames / itch.io / Poki 玩 5 分钟一局的网页小游戏；喜欢 Limbo、Inside、Celeste 的极简美学 | 上手快、失败成本低、有"我懂了"的顿悟时刻 | 55% |

**非目标用户**：追求叙事、成长线、社交与长线养成的玩家。本产品不做剧情、不做数值养成、不做多人。

- 不做账号体系、排行榜服务端（成绩仅本地存档）

## 三、核心玩法与游戏循环

### 3.1 三条铁律

1. **光是致命的。** 暴露状态下处于任意光源覆盖区域，暴露值以 1/0.6 每秒增长，满值即死。
2. **黑砖是同类。** 贴着黑砖且水平速度 < 34 px/s 持续 0.08 秒，进入"伪装"：眼睛闭合、描边消失、与砖块同色、全部光照判定跳过。
3. **移动即现身。** 任何水平输入、起跳、离开黑砖的瞬间，伪装立即解除，眼睛在 0.15 秒内完全睁开并自发光——这是黑暗里唯一可见的东西。

### 3.2 核心动词

| 动词 | 输入 | 状态 | 风险 | 收益 |
|---|---|---|---|---|
| 移动 | A/D 或 ←/→ | 暴露 | 高（光区必死） | 340 px/s，最快 |
| 跳跃 | Space / W / ↑ | 暴露 | 高（空中无法伪装） | 高度 130 px（≈4 格） |
| 冲刺 | Shift / Z | 暴露 | 高 | 900 px/s × 0.13 s ≈ 3.6 格，CD 0.8 s |
| 伪装 | 无输入（自动） | 免疫 | 无 | 完全免疫光，代价是 0 位移 |
| 重开 | R | — | — | 1 帧内重置本关（保留已收集碎片） |

**附带的"拟人化"规则（灯会愣一下）**：如果玩家在被光照到的瞬间完成伪装，对应那盏灯会**完全静止**地停在原地 3.6 秒、扇宽收窄到 82%，再用 0.9 秒平滑滑回原本的摆动轨道。不抖动——静止比抖动更像"愣住"。
它不是特效，是玩法：灯会在原地逗留，你最好别急着起身。这也是全片唯一一处"敌人有情绪"的表演。

**设计要点：伪装不是按键，是"什么都不做"。** 这让操作极简（3 个动作键），同时把心理压力放在"忍住不动"上——比按一个"隐身键"难得多，也更有戏剧性。

### 3.3 单关循环

```
 观察（灯的周期、光斑落点）
      ↓
 在安全岛上等待（伪装，眼睛闭合）
      ↓
 读秒 → 决定出击窗口
      ↓
 现身：跳 / 冲 / 跑（暴露，0.6s 生死线）
      ↓
 落地 → 立刻停住 → 重新伪装（若落点是硬砖则无法伪装，必须继续跑）
      ↓
 收集 3 枚碎片 → 传送门解锁 → 进入下一关
```

单关内循环的平均长度设计为 **4–7 秒**（一次"停—冲—停"），一关由 6–10 个这样的片段串成。

### 3.4 元循环

通关 → 记录单关用时与死亡数 → 解锁下一关（本地存档）→ 重玩刷新最佳成绩。
无养成、无解锁技能，保持"每一关都是同一个你"的纯粹性。

### 3.6 表现层机制（v1.0 新增，全部可单独关闭）

这五条的作用不是"好看"，是**让玩家在没死的时候也保持紧张**。全部通过 `FX` 开关可单独降级，方便 A/B。

| 机制 | 规则 | 目的 |
|---|---|---|
| **看守的眼睛** | 每一盏锥光都是一个"瞳孔"：白环 + 黑瞳，瞳仁朝视线方向偏移；玩家在光里消失时虹膜收缩、灯完全静止 3.6 s | 让光从"机关"变成"角色"，玩家会读情绪而不只是读周期 |
| **世界呼吸** | 全屏亮度以 24 s 为周期做 ±7% 起伏 | 对抗静态画面的习惯化，是零成本的抗厌倦装置 |
| **曝光负片** | 被光烧死时全屏反相 0.12 s，并在砖面留下轮廓烧痕，6 s 消散（最多 8 处） | 给失败一个"记得住"的画面；玩家的失误会留在地图上 |
| **活碎片** | 每关末位碎片会躲：玩家未伪装且靠近时缩进砖里（`liveIn→1`），伪装后才探出并被收取 | 把最后一次收集变成一个小博弈，强制复用伪装 |
| **影压** | 伪装瞬间背景向砖块塌陷一圈（230→14 px），现身时释放（10→132 px） | 给"融进去"这个动作物理重量，而不只是变色 |

### 3.7 反挫败设计

| 挫败点 | 对策 |
|---|---|
| 擦到光边就死 | 改成 0.6 秒灼烧条，配合屏幕红色暗角与噪声，给"还能救"的窗口 |
| 死亡后要重收碎片 | 死亡**不重置**已收集碎片，只重置位置与光源相位 |
| 不知道自己是否安全 | 三重反馈：眼睛开合 + 左下状态条（已伪装/暴露）+ 暴露条 |
| 不知道灯什么时候来 | 激光有 0.4–0.5 秒虚线预警，扫描灯的周期固定在 2–6 秒 |
| 手机误触 | 触屏按钮 64 px，独立区域，不遮挡视线中心 |

## 四、操作与交互设计

### 4.1 键位

| 功能 | 键盘 | 触屏 |
|---|---|---|
| 左 / 右 | A / D、← / → | 左下 ◀ ▶ |
| 跳跃 | Space、W、↑、J | 右下"跳" |
| 冲刺 | Shift、Z、K | 右下"冲刺" |
| 重开本关 | R | 暂停菜单 |
| 暂停 | Esc、P | 失焦自动暂停 |
| 静音 | M | — |
| 确认 | Enter（结算页） | 点击 |

**注**：参考产品使用 Z/X/C/V 作为 Booster 技能键；本产品简化为单一冲刺，理由是**新增技能会稀释"什么都不做"这个核心动词的注意力**。

### 4.2 手感规则

- 输入在固定步长内立即生效，不做插值延迟；渲染不插值（120 Hz 模拟对 60 Hz 渲染已足够平滑）。
- 跳跃：短按 0.42 倍切断，长按满高；起跳时立即播放粒子与音效，不做预备动作。
- 冲刺：冲刺期间重力衰减至 25%，可在空中使用，用于跨越 3.5 格内的亮区。
- 伪装：进入用 0.08 秒"沉降"（视觉上向下咬进砖块 4 px + 收敛环），解除是瞬时的（不能有延迟，否则玩家会觉得"明明按了还在挨打"）。
- 死亡：0.7 秒黑屏 + 粒子爆散 + 震屏，之后原地复活于关卡起点（无检查点，单关 < 90 秒）。

### 4.3 反馈优先级

同一帧内多事件冲突时的播放顺序：**死亡 > 被照射 > 碎片收集 > 伪装/解除 > 落地**。

## 五、关卡与难度设计

### 5.1 材质语法（关卡的设计语言）

| 元素 | 视觉 | 规则 | 作用 |
|---|---|---|---|
| 硬砖 HARD | 灰蓝 #2b3549，顶边 #3b4861 | 实体、挡光、**不可伪装** | 地形骨架、逼迫玩家暴露 |
| 黑砖 SOFT | 纯黑 #060606，顶边 #141414 | 实体、挡光、**可伪装** | 安全岛、路线节点 |
| 尖刺 | 灰蓝三角 | 触碰即死（伪装无效） | 禁止贴地拖时间 |
| 碎片 | 白色菱形 + 黑描边，比背景更亮 | 收集 3 枚解锁出口 | 强制路线完整遍历 |
| 墙中碎片 | 嵌在黑砖内部，只透出 26% 微光 | **仅伪装状态可拾取**（42 px 内自动过户） | 把伪装从防御手段变成探索手段 |
| 传送门 | 白色竖框，未解锁时为深灰 | 3 枚齐才可进入 | 关卡终点 |
| 灯锥 | 纯白扇形，随 sin 摆动 | 扫过区域暴露 | 节奏源 |
| 点光 | 圆形脉冲 | 半径随时间呼吸 | 局部禁区 |
| 激光 | 细亮线，间歇开关 | 有 0.4–0.5 s 虚线预警 | 门禁，训练读秒 |

**关键约束：地面永远是硬砖。** 玩家没法趴在起点不动就无敌，所有"安全"都必须靠跳跃到达黑砖获得。

### 5.2 MVP 关卡表

| 关 | 名称 | 尺寸（格） | 新要素 | 设计意图 | 目标时长 |
|---|---|---|---|---|---|
| 1 | 初暗 | 46×17 | 扫描灯锥 ×2 | 学会"站上黑砖、别动" | 30–45 s |
| 2 | 灼线 | 52×17 | 间歇激光 ×2、断崖、**墙中碎片** | 学会读灯周期与冲刺穿越；首次接触"融进墙里取东西" | 40–60 s |
| 3 | 巡灯 | 56×17 | 三灯交叉、脉冲点光、硬砖柱、**墙中碎片** | 学会在硬砖上被迫暴露、用柱子卡视线 | 50–75 s |
| 4 | 上升 | 44×17 | 垂直攀爬、竖激光 | 学会空中路线规划 | 45–70 s |
| 5 | 终局 | 60×17 | 全要素混合、高速灯、**墙中碎片** | 综合考核 | 60–90 s |

### 5.3 教学节奏（隐性教学）

| 关卡段落 | 教什么 | 怎么教 |
|---|---|---|
| L1 前 8 秒 | 移动/跳跃 | 无威胁平地 + 第一块黑砖就在出生点右侧 2 格 |
| L1 中段 | 伪装免疫 | 灯锥第一次扫过时，玩家恰好站在黑砖上（首次"它扫过但我没死"的顿悟） |
| L1 后段 | 硬砖不可伪装 | 灰砖走廊里灯扫过，必须靠冲刺通过 |
| L2 | 周期读秒 | 激光预警虚线 → 亮 → 灭，节奏固定 2.2 s |
| L3 | 空中暴露代价 | 硬砖柱之间无黑砖，跳过去就是赌命 |
| L4 | 纵向空间 | 灯从上方封路，只能贴黑砖等窗口 |
| L5 | 全部 | 无新机制，只加压 |

### 5.4 难度曲线

难度由四个旋钮控制，**每关只上调 1–2 个**：灯数量、灯速（0.55→1.65 rad/s）、黑砖密度（27→33 块/关）、硬砖断崖宽度（2→4 格）。

| 关 | 灯数 | 最高灯速 | 黑砖数 | 断崖 | 综合难度（1–5） |
|---|---|---|---|---|---|

## 六、角色与视觉风格

### 6.1 角色设定

- **形态**：22×24 px 圆角方块，比例接近正方形。
- **颜色**：暴露时 #000000；伪装时 #060606（与黑砖像素级一致），并**摊成脚下那一格砖**（32×32、网格对齐、方角、同顶边、同竖缝），只留 9% 白描边与一条闭眼缝。
- **表情**：只有两只 3×4.4 px 的白色眼睛，朝向前进方向。
  - 睁开 = 暴露，眼睛发白并在周围留一圈柔光——**这是全片唯一"活"的证据，也是光找到你的原因**。
  - 闭合 = 伪装，只剩一条 1 px、22% 透明度的缝。
- **无四肢、无面部细节、无口白**：所有情绪由"眼睛是否睁开"承担。

### 6.2 视觉语言

**单色重构（v2.0）**：全部取消色相，只保留四个明度层级 + 一种"材料"。完整规格见 `art/style-guide.html`。

| 层级 | 色值 | 用法 |
|---|---|---|
| 空气 | 背景渐变 #43484d → #5f646a + 静态颗粒 | 画面最大面积，永远不抢视觉 |
| 石头（硬砖） | #3a3f44，顶边 #4e555b | 可走不可藏 |
| 同类（黑砖 / 玩家） | #060606 / #000000 | 可藏；伪装后两者色值完全一致 |
| 光 | #ffffff | 锥光、点光、激光、暴露暗角，同一种白 |

**可读性三原则**：
1. 危险靠**亮度与形状**表达（尖刺是三角、激光是直线、光是最亮的白），不靠颜色。
2. 黑砖必须比背景暗得多（明度差 52 级），玩家在灰底上一眼就能认出"可藏面"。
3. 由于整体是亮的，危险提示改为**被光照白**（边缘白化），而不是传统的红色暗角——红了反而不符合这个世界。

### 6.3 光照渲染规格

- 光源在**独立离屏画布**上绘制，再以 `screen`（滤色）合成到主画布 → 在亮灰背景上得到"发亮"而不是"糊上一层白"的观感。
- 每个光源先铺一层**体积雾**（不参与遮挡的径向圆晕，峰值 5.5%），再按可见性多边形填充径向渐变（0/0.28/0.66/1 四段），让光束边缘有空气感而不是一块实心色板。
- 遮挡由 DDA 射线求得，硬边阴影，符合"光是粒子"的直觉；不做软阴影（成本与收益不匹配）。
- 灯本体 22 px 光晕 + 3.2 px 亮核，**永远可见**，玩家可以据此预判灯的位置。
- 画面四角 22% 黑色径向暗角，轻微压边聚焦。

|---|---|

| 解除 | 眼睛 0.15 s 内由缝张开至满高，描边同步淡入 |
| 跳跃 | 5 颗地面尘粒 + 上升音 |

## 七、音效与反馈

### 7.1 音频方案

**全程序化合成，零音频资源**（WebAudio Oscillator / 噪声缓冲 + 滤波器）。理由：包体从数百 KB 降到 0；音高可按状态实时调制；避免版权与加载失败。

### 7.2 音效表

| 事件 | 波形 | 频率 | 时长 | 音量 |
|---|---|---|---|---|
| 环境底噪 | 双正弦 55 Hz + 82.4 Hz + 320 Hz 低通，0.09 Hz LFO | — | 循环 | 0.055 |
| 跳跃 | triangle 420→620 Hz | 滑音 | 0.10 s | 0.16 |
| 冲刺 | 带通噪声 1800 Hz + saw 180→90 Hz | — | 0.16 s | 0.20 |
| 伪装 | 低通噪声 480 Hz + sine 140→90 Hz | 下滑 | 0.16 s | 0.10 |
| 解除 | sine 300→420 Hz | 上滑 | 0.09 s | 0.07 |
| 碎片 | sine 880 Hz → 1320 Hz 双音 | — | 0.09/0.14 s | 0.20 |
| 死亡 | saw 220→60 Hz + 500 Hz 噪声 | 下滑 | 0.40 s | 0.20 |
| 通关 | triangle 523/659/784/1046 Hz 琶音 | — | 0.22 s ×4 | 0.14 |
| 落地 | 320 Hz 短噪声 | — | 0.06 s | 0.09 |

### 7.3 动态混音

两条实时调制规则：

1. **暴露噪声**：1400 Hz 带通噪声，增益 = 暴露值 × 0.16，时间常数 60 ms。玩家在看不见血条边缘时也能"听见自己正在被烤"。
2. **闭眼闷音**：伪装瞬间全局低通从 20 kHz 压到 620 Hz（时间常数 70 ms），现身立刻恢复。闭眼之后听觉接替视觉，玩家会开始"听灯"而不是"看灯"。

这两条是本作最重要的音频设计：把不可见的危险变成可听的，把"闭眼"这件抽象的事变成能听见的事。

### 7.4 反馈矩阵

| 状态 | 视觉 | 听觉 | 触觉（移动端） |
|---|---|---|---|
| 已伪装 | 眼睛闭合、13% 白描边呼吸、状态条转空心 | 底噪 + 极低伪装尾音 | 无 |
| 暴露 | 眼睛发白、状态条转实心、身周柔光 | 底噪 | 无 |
| 被照射 | 暴露条、边缘白化、白色火星 | 噪声随暴露上升 | 可选：渐强短振动 |
| 即将死亡 | 画面边缘几乎全白、身体描边褪成白 | 噪声饱和 | 强振动 40 ms |
| 死亡 | 爆散 + 震屏 + 白闪残影 | 下滑音 | 长振动 80 ms |

## 八、技术方案

### 8.1 架构

```
index.html      结构：canvas + HUD + 4 个屏幕层（标题/暂停/结算/触屏）
style.css       视觉：玻璃拟态面板、HUD、响应式缩放
game.js         全部逻辑，单文件 IIFE，无模块打包
  ├─ 常量与数值表
  ├─ LEVELS[]        关卡数据（矩形描述，非字符画）
  ├─ Audio           程序化音频
  ├─ 瓦片与物理       AABB 分轴解算 + 固定步长
  ├─ 光照            DDA 射线 + 可见性多边形
  ├─ 实体            玩家/碎片/门/粒子
  ├─ 渲染管线
  └─ 状态机与 UI 绑定
```

**零依赖、零构建、零外部请求。** 双击 `index.html` 即可运行，也可直接丢到任意静态托管（含 `file://` 协议）。

### 8.2 渲染管线（每帧 6 步）

1. 主画布清屏为 #04050a。
2. **世界层**（相机平移）：硬砖/黑砖 → 尖刺 → 传送门 → 碎片 → 玩家 → 粒子。
3. **光照层**（离屏画布，独立相机变换）：逐个光源按可见性多边形填充渐变；再叠加玩家眼睛柔光、碎片/门的穿透光。
4. 光照层以 `lighter` 合成到主画布。
5. **前景层**：粒子（加法）、暴露红色暗角、四角暗角、通关白闪。
6. HUD 由 DOM 承担（不参与 canvas 重绘），按 60 ms 节流更新文本。

Canvas 按 `devicePixelRatio`（上限 2）放大，逻辑坐标恒为 960×544，CSS 等比缩放，移动端自动降为 1×。

### 8.3 光照算法（本作技术核心）

对每个光源：

```
for i in 0..N:                     // N = 130（锥）/ 170（点）
    a = 起始角 + 扇宽 × i / N
    d = castRay(光源, a, 射程)      // DDA 网格步进，遇实体格返回距离
    poly.push(光源 + 单位向量(a) × d)
fill(poly, 径向渐变)
```

- **DDA 而非逐像素采样**：每个格子只跨一次，单条射线 ≤ 64 步，5 个光源一帧约 1.3 万步，可忽略。
- **游戏判定与视觉同源**：`litBy()` 用同一套 `castRay` 判断玩家 5 个采样点（中心 + 四角）是否可见，保证"看起来被照到"与"判定被照到"一致。
- **容差**：视觉半径 = 逻辑半径 × 1.02，逻辑判定取 0.97 并在角度上内缩 0.02 rad → **玩家不会因为多边形锯齿被"看不见的光"杀死**（宁可少杀，不可错杀）。

### 8.4 物理

- 固定步长 1/120 s，累加器上限 8 步（切标签页回来不会瞬移）。
- 玩家为 AABB，分轴解算：先 X 后 Y，逐格检测；落地时用 1 px 探针补正 `onGround`，避免抖动导致土狼时间失效。
- 所有速度单位 px/s，与帧率解耦。

### 8.5 关卡数据格式

```js
{ id, name, cols, hint, spawn: [px, py],
  hard:  [[x, y, w, h], ...],   // 硬砖
  soft:  [[x, y, w, h], ...],   // 黑砖
  spikes:[[x, y, w, h], ...],
  keys:  [[tx, ty], ...],
  exit:  [tx, ty],
  lights:[{ type:'cone'|'point'|'laser', ... }] }
```

用**矩形**而非 ASCII 字符画：宽度 44–60 格时字符画极易错位，矩形描述可由代码校验（冒烟测试逐关检查出生点、碎片、出口均在空位）。新增一关 = 新增一个对象，不需要动引擎。

### 8.6 存档

`localStorage['umbra.save.v2'] = { unlocked: 3, best: { "0": 41.2, "1": 55.8 } }`
只存两项：解锁进度、单关最佳用时。隐私模式写入失败时静默降级（不影响游玩）。

### 8.7 运行平台与兼容性

| 平台 | 版本要求 | 说明 |
|---|---|---|
| Chrome / Edge | 最近 2 个大版本 | 主目标，60 fps |
| Safari（macOS） | 16+ | 需注意 `AudioContext` 需用户手势解锁（已处理） |
| Firefox | 最近 2 个大版本 | 无 `filter` 依赖，兼容良好 |
| iOS Safari | 15+ | 横屏，触屏按钮，`viewport-fit=cover` + 安全区 |
| Android Chrome | 10+ | 横屏，触屏按钮 |
| 微信内置浏览器 | 最近版本 | 无自动播放（音频在首次点击后初始化） |

依赖的 API：Canvas 2D、WebAudio、localStorage、requestAnimationFrame、Pointer Events。**无 WebGL、无 WASM、无 ES Module、无网络请求**，因此不存在跨域与 CORS 问题（`file://` 直开可用）。

## 十二、风险与开放问题

| 风险 | 影响 | 应对 |
|---|---|---|
| 玩家把"伪装"理解成"隐身键"而忽略静止要求 | 教学失败 | 首关强制在灯扫过时静止一次；眼睛开合足够直观 |
| 站在黑砖上无限等待导致节奏拖沓 | 体验变闷 | 灯周期上限 6 s；已列为 P0 的"烧砖"规则（见《创意与美术方向》2.3） |
| 移动端同时按方向+跳+冲刺的误触 | 操作失败 | 按钮间距 ≥ 12 px，直径 64 px，冲刺键独立小一号 |
| 手绘关卡复用度低 | 内容成本高 | 矩形数据格式 + 参数化灯配置，新增关卡约 20 分钟 |
| 与参考产品相似度过高引发争议 | 品牌风险 | 美术、音效、关卡全部自制；机制差异见 1.3 |

**开放问题**
1. 是否需要"伪装时缓慢贴墙移动"的进阶动作？（当前结论：不做，会削弱"停下"的张力）
2. 死亡是否应回退到最近黑砖而非关卡起点？（当前：起点，单关短所以可接受）
3. 是否加入单关计时排行榜（需服务端，与"纯前端"目标冲突）
