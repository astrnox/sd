### 1.3 玩法循环与 Booster

**循环结构**（依据 S1 官方文案与键位表还原）：

| 阶段 | 玩家动作 | 判定 / 反馈 | 循环出口 |
|---|---|---|---|
| 推进 | 方向键 / WASD 持续右移 | 关卡横向卷动，距离/分数累积 | — |
| 闪避 | Space 跳；躲避 "deadly lights" 与 traps | 触碰即失败 | R 重开 |
| 规避 | 进入阴影 / 光扫不到的位置 | 暂时安全 | 光相位变化后继续推进 |
| 加速 | Z / X / C / V 触发 Booster | **四个技能的具体效果未在 CrazyGames 官方页列明（待核实）** | — |
| 终止 | 失败 | 重开，不留痕迹（项目文档归纳，S22【内部】） | 回到起点 |

> **Booster 信息边界**：网页版仅能确认「四个键位存在」（S1【A】）。手游版的 "power-ups 提升速度与跳跃"、"每局获得属性点"（S4/S6【B】）属于**另一版本**的系统，不能据此推断网页版四技能内容。故本报告不列技能名称、不编造效果。

**与 UMBRA 的循环对照**：竞品是「**位置型**」循环（换地方躲），UMBRA 是「**状态型**」循环（换自己是什么）。这决定了两者对关卡语法的要求完全不同——前者靠陷阱密度堆叠制造难度，后者靠「安全岛链路 + 灯的相位」制造张力（`UMBRA_差异化说明.md`，S22【内部】）。

### 1.5 美术签名与 UX

- **签名**：黑白几何 + 暗底亮光 + 极简关卡。注意 **UMBRA 的世界明度是反的**（亮灰底、黑是「同类」不是「阴影」、光是唯一高光材料，S22【内部】）。这是最不易被指认为「像」的一层，建议在竞品章节用一张并置示意图说明（**示意图的张数与规范由 art-director 裁定**）。
- **UX 的三条可直接借用的做法**：键位外置、单键重开、横屏自适应。其中「键位外置」与 UMBRA 现有的标题页 `← → ↑ ≫` 键帽图示（`UMBRA_无文字叙事设计.md`，S22【内部】）是同一思路的两面——竞品外置到商店页，UMBRA 外置到标题页。**建议企划主笔在 GDD 里明确写出这层分工：商店页文案（游戏外三句）与标题页键帽（游戏内零字）分别承担什么**，避免被读成「抄了键位表」。

### 2.2 死亡即循环 / 环境叙事 / 世界记忆 / Rogue-lite 结构（四项专项）

**① 死亡即循环**。官方把整款游戏压成一句 "Kill, die, learn, repeat"（S9【A】）。关键在于**死亡不清除玩家的理解**：地图是程序化排列但「手工驱动」的（S12【B】），玩家反复经过同一地点时逐渐读懂它。UMBRA 的对应物是 `0.6 s（→T2）` 的可救窗口与失败后留下的烧痕——失败不是归零，是给关卡加一条证据。

**② 环境叙事：有一手开发者证言，建议直接引用进 GDD**。

> Motion Twin 首席设计师 Sébastien Bénard（GDC 2019，Engadget）：「At the beginning we did not want to have any kind of story… **We knew that the loop between dying and getting back into action should be as short as possible and lore was just getting in the way.**」——即：叙事让位于循环长度；EA 数月后因「玩家觉得世界有吸引力」才补了一个轻量故事，且刻意保持模糊，让玩家自己拼（S10【A】）。

这条证言的价值在于：它把「无文字 / 弱叙事」从美术选择提升为**节奏工程选择**——与 UMBRA「删掉全部文字是对的，但代价必须用别的东西付」（`UMBRA_无文字叙事设计.md`，S22【内部】）是同一判断的两种表述。

**③ 世界记忆**。Steam 社区共识：剧情主要靠 lore rooms、物品描述、环境线索拼出，「ambient storytelling, but no real narrative」；**仅在极后期（Rise of the Giant DLC、4+ Boss Cells）才出现脚本化过场与对白**（S11【B】，玩家观点 2020-07，非官方）。这正好给 UMBRA 划出分界：**UMBRA 连「极后期的解释」都不给**——结局刻意不解释、出口也是光（S22【内部】）。

**④ Rogue-lite 结构**。永久解锁（路径 / 武器 / 能力 / 突变）+ Boss Cells 难度分级（S9/S12【A+B】）。UMBRA 取的是**结构层**：手工房间池抽路线、灯相位 / 扫描方向 / 活碎片位置每局重随、局内零成长、跨轮痕迹保留、死亡回到起点但痕迹还在（S22【内部】）。对照之下，Dead Cells 提供的是「**循环是肉鸽的，内容也是肉鸽的**」，UMBRA 是「**循环是肉鸽的，内容是手工的**」——这一句建议作为 GDD 竞品章节的收束论断。

### 2.3 核心竞争力

1. **循环长度工程**：把「死→再动」压到最短，并让 lore 主动让路（S10【A】）。
2. **双重进度**：每轮会失去一切，但每次都永久多懂一点地图——失败被转化为进展（S9/S12【A+B】）。
3. **编排质量 + 随机性的配比**：程序化排列但手工驱动关卡，避免纯随机地图的塌方（S12【B】）。
4. **长期内容信誉**：近 7 年免费更新 + 明确「无微交易」（S10/S12【A+B】），把买断制做成长尾口碑。

### 3.2 专项：无文字叙事的「因果可读性」——玩家如何「看懂」而非猜谜

这是本项目最需要向 Playdead 借、也最需要与之划界的一节。

**Playdead 的可读性机制（四条，均可追溯到来源）**：

| 机制 | 做法 | 来源 |
|---|---|---|
| 危险是「环境事实」而非「规则说明」 | 锯片、电网、毒水、塌陷结构直接摆在场景里，不给上下文、不给警告；玩家从「男孩持续向前 + 环境敌意递增」推断出有事不对 | S17【B】 |
| 极简控制集 = 极小的解空间 | 只有跑 / 跳 / 抓，玩家不需要在「我该按什么」上消耗注意力，全部注意力用于「这里在发生什么」 | S15【B】 |
| 声音承担提示职责 | 无 BGM，木头吱呀、蜘蛛爬动、落地的闷响各自对应一个可学事件；安静本身成为节拍器 | S17【B】 |
| 死亡是教学，不是惩罚 | 高频检查点 + 明确死亡演出 + 快速重试，把「试错」变成合法的学习方式 | S17【B】 |

**关键分野（建议直接写进 GDD）**：

| | Playdead（Limbo / Inside） | UMBRA |
|---|---|---|
| 无文字的目的 | ** withholding**：故事由「被隐去的东西」构成，玩家填的是**意义** | **transparency**：规则由「被画出来的东西」构成，玩家填的是**因果** |
| 玩家该得到的 | 一个挥之不去的疑问（"what happened to her?" 永不作答，S17【B】） | 一次顿悟（"为什么这块砖闭着眼？" → 站上去不动 → 灯扫过没死） |
| 猜谜的地位 | 是设计目标（开发者拒绝确认解读，S17【B】） | 是**失败信号**（项目文档定义：「玩家没发现伪装」「我不知道我在干嘛」需处置，S22【内部】） |
| 兜底手段 | 氛围可兜底，读不懂仍可继续 | 文字被删后无兜底；项目文档已诚实登记「做关卡的时间是写文案的 5 倍」「一个玩家没看懂，就是真的卡住」（S22【内部】） |

> **由此得出一条可直接采纳的设计判据**：UMBRA 的每一处无文字引导，都应能回答「玩家看懂的是**规则**还是**气氛**？」——若只产出了气氛，就退回重做场景。项目 `UMBRA_无文字叙事设计.md` 的「一关只教一件事」表与「三个陌生人盲测（首次伪装 < 15 s / 首次死亡后重试 < 5 s）」（S22【内部】）已经是把这条判据操作化了的验证方案，**本报告不改动其中任何数值**（均为 designer 域）。

### 3.3 核心竞争力

1. **把「删掉」做成方法论**：零对白 / 零 HUD / 零教程 / 零提示仍能让全球玩家独立完成 3–5 小时流程（S17【B】）。
2. **视听即教学**：环境声与剪影承担了文案的全部职责（S17/S15【B】）。
3. **克制带来的解释空间**：结局不解释反而成为长期讨论与媒体高分来源（S14【B】，IGN 10/10 明确点名"twist… will fuel heated discussion"）。
4. **低失败成本**：密集检查点让 trial-and-death 不劝退（S17【B】）。

### 5.1 四款竞品的核心竞争力总结（3–5 条，格局层）

1. **「一条规则撑起全部内容」是这条赛道的共同底层能力**：Closure 的「被照到才存在」、Sqube 的「躲进阴影」、UMBRA 的「静止即伪装」都是单规则自证，不依赖文本解释（S1/S19【A】+ S22【内部】）。
2. **短重试是硬共识**：Sqube 的 R、Closure 的 Select、Dead Cells 的「lore 让路于循环」、Limbo 的密集检查点，四者从不同方向把「失败→再试」压到最短（S1/S9/S10/S17/S20）。
3. **删掉文字后，代价必然转移到关卡与反馈通道**：Playdead 用声音与剪影、Closure 用光照即反馈、UMBRA 用图标 / 静态线索 / 烧痕 / 插座 / 状态方块（S15/S17/S18/S20【B】+ S22【内部】）。
4. **「世界记得你」是尚未被这四款共同占据的位置**：Closuer/Sqube 重开即重置、Limbo/Inside 线性不回头、Dead Cells 记住的是**玩家的解锁**而非**玩家的失误**。UMBRA 把失败痕迹跨轮留在地图上，是可主张的空白（分析【C】，基于以上四款事实）。
5. **网页极简几何已被验证可跨端长跑**：Sqube 系列 2021→2026、Closure 2009 Flash→2012 多平台，说明该美术语法抗疲劳（S1/S4/S18/S19）。此条供 art-director 参照，**不含任何美术资源项数**。

## 6. 市场空白与 UMBRA 的差异化假设

### 6.1 三个空位（基于 §5 对比，属推断【C】）

| 空位 | 谁占据了邻近位置但没占住这一点 | 依据 |
|---|---|---|
| **空位 A：把「伪装」做成状态机，而不是位置 / 隐身 / 显形** | Sqube 是「站到光扫不到的地方」（位置），手游版虽写 "fit right in the environment" 但官方文案仍是 hide/run/runner；Closure 是「光决定地形是否存在」；无一款把「你此刻是什么材质」做成唯一判定 | S1/S4/S19/S20 + 分析【C】 |
| **空位 B：让「光」成为有意志、会迟疑的对手** | Sqube 的光是 deadly lights（机械/致命），Closure 的光是玩家的工具，Playdead 的光是氛围；「灯会因你消失而愣住」未被占据 | S1/S17/S19/S20 + S22【内部】 |
| **空位 C：无文字 + 短局 + 跨轮世界记忆三者同时成立** | Dead Cells 有循环与记忆但靠物品描述/后期对白；Playdead 无文字但线性一次性、无循环；Sqube 短局但重开即忘 | S9/S10/S11/S17/S1 + 分析【C】 |

> ⚠️ **空位 A 的成立条件取决于口径**：同 IP 手游版已有 "fit right in the environment" 与 "watchful Eyes" 的**商店文案**（W3，S4/S6【B】）。因此 GDD 里不宜写「从未有人做过」，应写「**在浏览器短局、以状态判定为核心、且失败痕迹跨轮累积的组合上，未见于本次四款对标**」。措辞收窄后仍成立，且不可被一句话反驳。

### 6.2 UMBRA 的差异化假设（3–5 条，均为**假设，待验证**）

| # | 假设 | 支撑事实 | 可证伪条件（供 playtest 设计参考，不含数值） |
|---|---|---|---|
| H1 | **「停止」作为唯一动词，能撑起短局重复可玩性**，而不必依赖技能 / Build / 数值成长 | 四款竞品分别靠位置躲藏、战斗 Build、机关解谜、光照解谜；均未把「不动」做成核心动词。项目已定「动词只有一个：停止」（S22【内部】） | 若玩家在盲测中把伪装读成「等安全了再走」而非「我在演」，则状态感未成立 |
| H2 | **失败痕迹跨轮保留，能把「重开」变成叙事而非归零** | Dead Cells 记住的是解锁、Sqube 重开即忘；UMBRA 的烧痕 / 轮廓 / 灯迟疑 `→T3` 记住的是失误（S9/S10/S1 + S22【内部】） | 若玩家把跨轮痕迹读成「画面变脏 / 贴图」而非「有人来过」，则该通道失败（项目文档已登记同类风险，S22【内部】） |
| H3 | **「无文字 = 让因果被看懂」在短局里比「无文字 = 留白」更适配核心玩家** | Playdead 的沉默是主题性的、猜谜是目标；UMBRA 把猜谜定义为失败信号（§3.2，S17 + S22【内部】） | 若三个陌生人盲测中「首次伪装」与「首次死亡后重试」达不到项目自定目标，说明场景编排没把规则画清楚（目标值为 designer 域，本报告不引用为结论） |
| H4 | **浏览器纯前端 + 极简几何 + 零游戏内文字**，能同时拿到「点开即玩」与「本地化成本为零」两项红利 | Sqube / Closure 的网页路径（S1/S18/S19），项目文档自述本地化成本为零（S22【内部】） | 若门户分成必须集成平台 SDK，则「零外部请求」的技术前提被打破（§1.6，待 tech-planner 裁决） |
| H5 | **短局结构（现状 `→T4`）比长局更贴合网页平台会话习惯**；正式版若拉长需靠「可中断 / 可续」补偿 | CrazyGames 官网设 "5-minute fun" 分类、平台以短会话休闲为主（S3【A】+ S21【B】行业分析） | `待定（T9，草案：8–12 min）` 若在 playtest 中出现明显中途流失，需由 designer 重新裁定节奏 |

> H1–H5 是**差异化假设**，不是设计定论；验证方案与阈值属于 designer 域，本报告不提供数值。
